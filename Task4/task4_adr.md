# ADR: передача актуальных ставок по депозитам в колл-центры

Автор: Алексей Головизин

Дата: 02.07.25

# Проблема

В банке есть персональные ставки депозитов для существующих клиентов.

Эти ставки рассчитываются в зависимости от того, сколько у клиента денег в банке, и других параметров. Обновляются ежесуточно.

Клиенты часто прибегают к консультации по телефону, и оператор колл-центра (и банковского и партнёрского) должен рассказать посетителю-клиенту, какие для него есть персональные ставки по депозитам.

Для этого операторы колл-центра (банковского и партнёрского) должны иметь возможность быстро просмотреть информацию о персональных предложениях по депозитам для клиента, который им звонит – или просто об актуальных ставках по депозитам, если звонит не клиент банка.

Систему банковского колл-центра можно доработать по нашему заказу, систему партнёрского колл-центра доработать не получится, представители партнёрского колл-центра предлагают пересылать им данные в виде файлов (вероятно, Excel-файлов).

# Решение

В сервис депозитов:

* добавить эндпоинт поиска информации о персональных ставках по депозитам для существующих клиентов (по телефону и ФИО)  
* поддержать RBAC-модель;  
* добавить роли пользователей: CallCenterEmployee, CallCenterSupervisor;  
* для супервайзеров: добавить эндпоинты управления учётками своих операторов:  
  * просмотр списка учёток операторов, зарегистрированных данным супервайзером;  
  * добавление нового оператора;  
  * удаление оператора.  
* добавить эндпоинты входа в систему по логину-паролю для операторов и супервайзеров колл-центра;  
* поддержать ограничение количества запросов от одного оператора (чтобы исключить скриптинг с пробивом баз телефонных номеров);  
* поддержать логирование поисковых запросов.

Во фронтэнд сайта:

* добавить страницу входа-выхода в систему (для операторов и супервайзеров колл-центра);  
* добавить страницу поиска персональных депозитов для клиента по номеру телефона или ФИО (для операторов партнёрского колл-центра);  
* добавить страницу управления учётками своих операторов (для супервайзеров колл-центров).

В системе банковского колл-центра:

* поддержать панель “персональные депозиты клиента” со следующим функционалом:  
  * запросить эндпоинт поиска персональных ставок по депозитам в сервисе депозитов;  
  * показать персональные ставки для этого клиента прямо в системе колл-центра, если клиент найден.  
* поддержать ввод логина-пароля для учётки в сервисе депозитов, если оператор в смене ещё не залогинился.

Также нужно провести инструктаж для операторов и супервайзеров колл-центров (отдельно для банковского, отдельно для партнёрского).

# Use Cases

## UC-1: оператор партнёрского колл-центра ищет информацию по депозитам для клиента

### Действующие лица

* Посетитель сайта банка  
* Сотрудник партнёрского колл-центра

### Основные системы

* Фронтэнд сайта  
* Сервис депозитов

### Описание

* Сотрудник колл-центра открывает специальную страницу сайта (/deposit/search\_personal\_proposals)  
* Для продолжения при первом открытии сайта ему предлагают залогиниться под своим логином-паролем, токен сессии действует до 14 часов.  
* Если сотрудник колл-центра залогинился успешно, ему доступна страница поиска персональных предложений по депозитам по телефону пользователя или его фамилии-имени:  
  * сотрудник копирует телефон звонящего или вбивает ФИО;  
  * сотруднику показывают, какие предложения по депозитам доступны для звонящего (те же самые, что сам звонящий может увидеть в интернет-банке, если он уже клиент, или на сайте, если ещё не клиент).

Важно: формочка логина-пароля должна работать быстро, так что сотрудник колл-центра должен успеть залогиниться, не прерывая звонок, даже если он обрабатывает первый звонок за смену.

Важно: сотрудник колл-центра не может делать более 1 поиска в секунду (если больше, он должен ожидать ответа сервера).

Важно: в БД сервиса депозитов должна оставаться история поиска сотрудника колл-центра.

## UC-2: супервайзер партнёрского колл-центра просматривает и редактирует своих сотрудников с ролью CallCenterEmployeе

### Действующие лица

* Супервайзер группы банковского колл-центра

### Основные системы

* Фронтэнд сайта  
* Сервис депозитов

### Описание

* Супервайзер группы колл-центра заходит на специальную страницу сайта (/deposit/call\_center\_user/list), техническую учетку супервайзера ему создали заранее через админку сервиса депозитов.  
* Супервайзер видит таблицу своих юзеров (логин, email, телефон).  
* Супервайзер может нажать кнопку “удалить пользователя” напротив любого из них  
* Супервайзер может нажать кнопку “добавить нового сотрудника” и ввести его логин, пароль и телефон в форме ввода.  
* После этого сотруднику колл-центра на email и по SMS приходит логин-пароль от его учётки.  
* В случае успеха регистрации супервайзеру показывают сообщение, что пользователь успешно добавлен и список перезагружается.

## UC-3: оператор банковского колл-центра ищет информацию по депозитам клиента

### Действующие лица

* Посетитель сайта  
* Оператор банковского колл-центра

### Основные компоненты

* Сервис депозитов  
* Система банковского колл-центра

### Описание

* Оператор банковского колл-центра принимает звонок клиента.  
* Звонящий просит консультацию по депозитам.  
* Если телефонный номер не определился, оператор спрашивает у звонящего, является ли он клиентом банка.  
* Если не является:  
  * оператор в своей системе переключается на вкладку “депозиты”, где подтянута информация о станадртных условиях депозитов для новых клиентов.  
* если звонящий является клиентом:  
  * оператор спрашивает его ФИО и вбивает в систему:  
  * оператор переключается на вкладку “депозиты”, где запускается поиск по номеру телефона / ФИО клиента  
  * если поиск прошёл удачно, то оператору показывают актуальные персонализировнные условия депозитов для этого клиента;  
  * если клиент не найден, то оператору подсвечивают, что клиент с таким номером/ФИО не найден, и показывают станадртные условия депозитов для новых клиентов.

# Отклонённые альтернативы

## Рассылать Excel-файл с актуальными процентами по депозитам

Есть вариант: отправлять в колл-центр (партнёрский и наш) Excel-файл с актуальными предложениями по депозитам для каждого пользователя.

### Плюсы

Простота.

### Минусы

* по условию задачи сказано, что надёжного канала связи у нас нет;  
* такой Excel-файл – это, по факту, список клиентов банка. Плюс по нему можно понять, у кого из клиентов на счетах больше всего денег.  
  * список клиентов банка сам по себе составляет банковскую тайну (а я не уверен, что партнёрский колл-центр проходил сертификацию по работе с ней);  
  * сотрудники колл-центра могут впасть в искушение и продать этот список днепровским офисникам, что особенно опасно для банка с массой клиентов-пенсионеров.

## Сделать общий SSO для сервиса депозитов и клиентского сервиса

Есть вариант поддержать единый сервис аутентификации и авторизации для депозитов и для кредитов.

### Плюсы

Супервайзерам колл-центров не придётся создавать отдельные учётки для просмотра информации о персональных процентах по депозитам (в сервисе депозитов) и для просмотра информации о персональных предложениях по кредитам (в сервисе кредитов).

### Минусы

Несчастный “архитектор” пока не умеет в SSO, так что запроектировать такой сервис пока не может. Если не выгонят с вашего курса до 9 спринта, то есть шанс, что там научат – но это будет уже потом \= )

# Недостатки, ограничения, риски выбранного решения

* Супервайзеров надо добавлять вручную через админку сервиса.  
* Супервайзерам придётся добавлять сотрудников отдельно для сервиса депозитов, и отдельно для сервиса кредитов.  
* Сотрудников, имеющих право искать информацию по депозитам, придётся добавлять заранее.

Неудобно, но на первое время должно сгодиться.
