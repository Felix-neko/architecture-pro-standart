# Задание 2: Требования по FURPS+ для MVP (6 месяцев)


| Код       | Требования                                                                                                              | Комментарий  |
|-----------|-------------------------------------------------------------------------------------------------------------------------|--------------|
| **F**     | **Функциональные (Functionality)**                                                                                      |              |
| F-1       | Сайт: показывать актуальные ставки по депозитам                                                                         | Просто актуальные стандартные ставки по депозитам, без персонализации.  |
| F-2       | Сайт: получение контактов клиента через форму обратной связи с заявкой на депозит                                       | Получить контакты, передать в колл-центр для обратного звонка.  |
| F-3       | Скоринг: добавить процесс регулярного расчёта процентов по депозитам                                                    |  |
| F-4       | Интернет-банк: показывать авторизованному клиенту список доступных депозитов с персональными ставками                   |  |
| F-5       | Интернет-банк: приём заявок на открытие депозита                                                                        | Клиент кликает на депозит, выбирает в форме заявки срок и указывает сумму.  |
| F-6       | Интернет-банк: подтверждение заявок на открытие депозита через SMS                                                      |  |
| F-7       | Интернет-банк: отправка заявки на депозит в бэк-офис (отдел депозитов)                                                  | для дальнейшей обработки по старому процессу.  |
| F-8       | Сайт: показывать актуальные предложения по кредитам со стандартными ставками                                            |  |
| F-9       | Сайт: получение заявки на кредит через расширенную форму обратной связи (с паспортными данными)                         |  |
| F-10      | Скоринг: регулярный предварительный скоринг для всех клиентов                                                           | Для последующего показа предодобренных предложений по кредитам в интернет-банке |
| F-11      | Интернет-банк: показывать авторизованному клиенту предодобренные предложения по кредитам                                |  |
| F-12      | Интернет-банк: получение заявки на предодобренный кредит                                                                | с последующим скорингом на стороне банка, но по упрощённой и ускоренной процедуре.  |
| F-13      | Интернет-банк: подтверждение заявки на кредит через SMS                                                                 |  |
| F-14      | Интернет-банк: поддержать отправку заявки на предодобренный кредит для дальнейшей обработки в бэк-офисе                 |  |
| **U**     | **Удобство использования (Usability)**                                                                                  |              |
| U-1       | При дизайне придерживаться банковского фирстиля и системы дизайна                                                       |              |
| U-2       | Пользовательский интерфейс должен быть протестирован на пенсионерах                                                     | Хотя бы в части нового функционала по депозитам и кредитам |
| **R**     | **Надёжность (Reliability)**                                                                                            |              |
| R-1       | Сайт: использовать шифрование трафика при обработке форм обратной связи                                                 |              |
| R-2       | Интернет-банк: использовать шифрование трафика при всех операциях                                                       |              |
| R-3       | По возможности: хостинг боевой версии интернет-банка перенести внутрь банка                                             | Так как бэкэнд интернет-банка имеет доступ к БД АБС, что чревато утечками |
| R-4       | Все сервисы должны работать с доступностью 99.9%                                                                        | Т.е. простаивать не более 14.4 минут в сутки |
| R-5       | Интернет-банк не должен напрямую работать с API АБС в части функционала депозитов                                       |              |
| R-6       | Предусмотреть горизонтальное масштабирование всех БД и сервисов в рамках нескольких ЦОДов на случай сбоя в основном ЦОДе | на перспективу |
| **P**     | **Производительность (Performance)**                                                                                    |              |
| P-1       | Обеспечить 95%-й отклик бэкэнда (в части депозитов) 200 мсек                                                            | 99%-й до 500 мсек |
| P-2       | Предрасчёты скорингов считать НЕ в течение рабочего дня по европейской части РФ                                         |              |
| **S**     | **Поддерживаемость (Supportability)**                                                                                   |              |
| S-1       | Новый функционал интернет-банка по открытию депозитов вынести в отдельный микросервис                                   | Т.к. ASP.NET 4.5 не умеет работать с Kafka, можно реализовать его на Python |
| S-2       | Нужно разрабатывать документацию для дальнейшего расширения системы                                                     |              |
| S-3       | Использовать версионирование API                                                                                        | Для поддержания обратной совместимости |
| **+REST** | **+ Ограничения (Restrictions)**                                                                                        |              |
| REST-1    | Функционал работы с SMS дорабатывать внутри банка, а не силами аутсорс-компаний                                         | Считаем, что реализовывать такое придётся часто, нужно уметь делать силами штатных сотрудников |
| REST-2    | По возможности, использовать MS SQL и Oracle в качестве СУБД                                                            | по ним в банке уже есть экспертиза |
| REST-3    | Если понадобится очередь сообщений -- использовать Kafka                                                                | на перспективу |
| REST-4    | Предпочтительно использовать языки программирования и фреймворки, на которых в банке уже ведётся разработка             |              |
